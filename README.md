# CRM: звонки и встречи

REST API для учёта организаций, звонков и встреч менеджеров. Интерфейса нет.

## Запуск

Одна команда из корня репозитория:

```bash
docker compose -f docker/docker-compose.yml up --build
```

API: `http://localhost:14325`. Документация: `http://localhost:14325/docs`.

PostgreSQL поднимается рядом и с хоста доступен на порту 5433. Миграции применяются сами до старта uvicorn. Файл `.env` уже лежит в корне: с хоста `POSTGRES_HOST=localhost` и `POSTGRES_PORT=5433`.

Переменные:

```
POSTGRES_HOST=localhost
POSTGRES_PORT=5433
POSTGRES_USER=crm
POSTGRES_PASSWORD=crm
POSTGRES_DB=crm
```

## Тесты

Нужен запущенный Postgres (достаточно `docker compose -f docker/docker-compose.yml up -d postgres`) и зависимости:

```bash
poetry install
poetry run pytest
```

Тесты сами накатывают миграции и перед каждым тестом очищают таблицы `crm`.

## Запросы

Примеры лежат в `requests.http`. Порт тот же, `14325`. Идентификаторы в файле — `1`, если база пустая и запросы идут по порядку.

## Эндпоинты

- `POST /companies` — название, БИН (12 цифр), телефон
- `GET /companies?status=&page=&size=` — фильтр по статусу и страницы
- `POST /managers` — менеджер, без него невозможно создать встречу
- `POST /meetings` — встреча менеджеру, в теле только `start_time`
- `PATCH /meetings/{id}` — перенос (`start_time`) или отмена (`status=cancelled`)
- `POST /calls` — `no_answer`, `refused`, `meeting_set`
- `GET /managers/{id}/schedule?date=` — расписание на день

Время в теле запросов и ответах — UTC, ISO 8601, с часовым поясом. `date` у расписания — календарный день Asia/Almaty.

## Правила

Длительность встречи всегда 60 минут, конец считает сервер. Встреча целиком помещается в пн–пт, 09:00–18:00 Asia/Almaty. Старт в 17:00 допустим, старт в 17:30 — нет.

Пересечение полуоткрытое: 10:00–11:00 и 11:00–12:00 можно. Две активные встречи одного менеджера в одном слоте нельзя. Две активные встречи одной организации в одном слоте нельзя, даже у разных менеджеров. Отменённая встреча слот освобождает.

`original_scheduled_at` ставится при создании и при переносе не меняется.

Звонок `meeting_set` обязан ссылаться на уже созданную активную встречу этой же организации. Иначе 422. Сначала `POST /meetings`, потом `POST /calls`.

Статус организации берётся из последнего звонка: `no_answer` → `called`, `refused` → `refused`, `meeting_set` → `meeting_set`. До звонка статус `new`.

Чужой слот, повторный БИН и пересечение — 409. Нет организации, менеджера или встречи — 404. Нерабочее время, пустой `meeting_set` и неизвестный статус — 422.

Два одновременных назначения на один слот сериализуются блокировкой строк компании и менеджера. Если проверка в коде всё же разъедется, вставка упрётся в ограничение PostgreSQL `EXCLUDE` и тоже вернёт 409.
