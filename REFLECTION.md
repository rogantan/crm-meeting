# REFLECTION

## Два менеджера одновременно жмут назначить на один слот

Сейчас оба запроса попадают в одну и ту же последовательность. Транзакция сначала блокирует строку компании, потом строку `SELECT ... FOR UPDATE`, и этот порядок одинаковый на создании и на переносе, чтобы не словить deadlock. После блокировки сервис проверяет активные встречи полуоткрытым интервалом и только потом вставляет строку. Вторая транзакция ждёт первую. Когда первая фиксируется, вторая видит занятый слот и отвечает 409 с текстом, кто именно занят: менеджер или организация.

Если под нагрузкой дубль всё-таки пройдёт мимо проверки в Python, его остановит ограничение базы `EXCLUDE USING gist` по `tstzrange` отдельно для менеджера и для организации. Оно включено только для `status = scheduled`, поэтому отмена слот освобождает. Такая ошибка ловится и тоже становится 409, а не 500.

## 5 вопросов

Самым сложным оказалось время. API принимает UTC, а окно 09:00–18:00 считается в Asia/Almaty, и вся встреча должна в него влезть: 17:00 можно, 17:30 уже нет. Рядом с этим легко ошибиться в пересечении и посчитать стык двух встреч конфликтом.

Из-за четырёх часов нет авторизации, журнала каждого переноса и отдельной очереди. История переноса — это одно поле `original_scheduled_at`. `POST /managers` добавлен сверх минимального списка: иначе встречу некому назначить.

Ещё за восемь часов я бы сделал таблицу всех историй встречь, авторизацию,  ключ идемпотентности на создание встречи и отдельный тест, где два запроса идут реально параллельно, а не только проверка ограничения прямым SQL.

Подсказка с `EXCLUDE USING gist` по `tstzrange`, написание тестов и примеров HTTP-запросов, также вопросы про timezone

Непонятно, создаёт ли звонок `meeting_set` встречу сам или только ссылается на неё. В модели звонка уже был `meeting_id`, поэтому встреча создаётся отдельной ручкой, а звонок без неё — 422. Статус организации меняет последний звонок. День в расписании — календарный день Алматы, тело запросов — UTC. Отменённая встреча слот не держит: в условии речь про активные встречи.
